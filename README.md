# Sahayam v2 — build-ready

Malayalam-first, ML-assisted disaster coordination for Kerala floods. One codebase gives you:

- a **FastAPI backend** (ML triage, SMS gateway, misuse screening, alerts, logins), which also serves the web app, and
- an **Android app (APK)** built with Capacitor from the same web app, working offline with an SMS fallback.

```
sahayam-v2/
├── backend/     FastAPI server + ML triage + SQLite (serves frontend/ at http://<server>:8000/)
├── frontend/    Built web app (generated by web/, served by the backend)
├── web/         App source (src/app.jsx, src/styles.css) + build script
└── mobile/      Capacitor Android project
    ├── config.js    ← the server address the phone app uses (edit this)
    ├── www/         Built web app for the phone (generated by web/)
    └── android/     Native Android Studio project
```

---

## 1. Run the backend (your laptop or a server)

Needs Python 3.10+.

```bash
cd backend
pip install -r requirements.txt
uvicorn main:app --host 0.0.0.0 --port 8000
```

- Open **http://localhost:8000/** in a browser. The app finds the server by itself.
- `--host 0.0.0.0` lets phones on the same Wi-Fi reach it. On Windows, allow Python through the firewall when asked.
- First start creates `sahayam_v2.db` with a demo scenario. Delete that file to start fresh.

### Demo accounts

| Role | Username | Password |
|---|---|---|
| Control room | `admin` | `admin123` |
| Volunteer | `arjun` / `divya` / `rahul` | `arjun123` / `divya123` / `rahul123` |
| Volunteer (waiting for approval) | `meera` | `meera123` |

Citizens never log in.

## 2. Build the APK

### One-time setup
1. **Node.js 22 or newer** (Capacitor 8 requires it): https://nodejs.org
2. **Android Studio** (latest stable). It installs the Android SDK and its own Java 21.
   On first launch, let it finish downloading the SDK.

### Point the app at your server
Edit **`mobile/config.js`**:

```js
window.SAHAYAM_CONFIG = { apiBase: "http://192.168.1.20:8000" };
```

- **Same Wi-Fi demo:** your laptop's IP address. Find it with `ipconfig` (Windows) or `ip addr` / `ifconfig` (macOS/Linux).
- **Hosted server:** `https://your-server.example.org`.
- Wrong address or IP changed? You can fix it on the phone without rebuilding: **Sign in screen → Server → enter address → Test → Save and restart**.

### Build
```bash
cd web
npm install
npm run build          # compiles the app into ../frontend and ../mobile/www

cd ../mobile
npm install
npx cap sync android   # copies www/ into the Android project
npx cap open android   # opens Android Studio
```

In Android Studio: wait for "Gradle sync" to finish (first time downloads a few hundred MB), then
**Build → Build App Bundle(s) / APK(s) → Build APK(s)**.
The APK appears at:

```
mobile/android/app/build/outputs/apk/debug/app-debug.apk
```

**Or run it directly:** enable *Developer options → USB debugging* on your phone, plug it in, press ▶ Run.

Command-line alternative (after `npx cap sync android`): `cd mobile/android && ./gradlew assembleDebug`
(`gradlew.bat assembleDebug` on Windows).

### Install on phones
Send `app-debug.apk` over WhatsApp/Drive. On the phone, allow *Install unknown apps* for the app you open it with.

### Release build (for distribution)
**Build → Generate Signed App Bundle / APK → APK**, create a keystore once and **keep it safe** — you can't publish updates without it.

## 3. What the Android app does natively

| Feature | How |
|---|---|
| GPS location | WebView geolocation; Android asks for location permission on first use |
| Video / voice messages | Camera and recorder open from the file input; uploaded to the server |
| Call 112 / call volunteer | Opens the phone dialer |
| Offline SMS fallback | Opens the SMS app with the message pre-filled; details and video upload automatically when back online (outbox kept on the phone) |
| Vibration on SOS | Vibration API |
| Works without internet | React, Leaflet and fonts are bundled; nothing loads from a CDN |

Permissions declared in `mobile/android/app/src/main/AndroidManifest.xml`: internet, network state,
location, camera, microphone, vibration.

`android:usesCleartextTraffic="true"` is on so the app can reach `http://` laptop servers during a demo.
**Remove it for production** and serve the backend over HTTPS.

## 4. Changing the app

Edit `web/src/app.jsx` (React, one file) or `web/src/styles.css`, then:

```bash
cd web && npm run build
cd ../mobile && npx cap sync android
```

The same build also refreshes `frontend/`, so the browser version served by the backend stays in step.

**Modes** — the app decides by itself:
- `config.js` has an address → **live**. If the server can't be reached, it behaves as offline (SMS path), never as demo.
- Opened from the backend with no address → **live** on the same server.
- No address inside the Android app → **demo** with sample data (a "Demo" tag shows in the header).

## 5. SMS gateway (optional, for real SMS)

By default every outgoing SMS (status replies, alerts, one-time codes) is written to the `sms_log`
table as an outbox, and one-time codes are shown in the app as a demo. For real SMS:

1. Get a Twilio number (or an Indian provider — MSG91, Gupshup, Exotel; bulk alerts need DLT-registered templates).
2. Start the backend with:
   ```bash
   export SMS_PROVIDER=twilio TWILIO_ACCOUNT_SID=AC... TWILIO_AUTH_TOKEN=... TWILIO_FROM=+1...
   export SMS_WEBHOOK_SECRET=pick-a-long-random-string
   ```
3. In Twilio, set the number's incoming message webhook to
   `https://<your-server>/api/sms/incoming?secret=<SMS_WEBHOOK_SECRET>` (HTTP POST).
4. Put the same number in `SMS_GATEWAY` / `SMS_GATEWAY_DIAL` near the top of the SMS section in `web/src/app.jsx`, and rebuild.

Accepted formats: the app's compact `SHM1 RES 9.9816,76.2999 P3 FEC text…`, and
`HELP <place> <message>` from any phone (place names are matched to Kerala towns and districts).

## 6. Hosting the backend (so phones work anywhere)

Any Python host works (Render, Railway, a college server, a VPS):

```
Start command:  uvicorn main:app --host 0.0.0.0 --port $PORT
Root directory: backend
```

The backend serves `../frontend`, so deploy the whole folder, not just `backend/`.
SQLite and uploaded videos live on local disk — on hosts with temporary disks, attach a persistent
volume or switch `SAHAYAM_DB` to PostgreSQL (`postgresql+psycopg://…`, add `psycopg[binary]` to requirements).

## 7. What's new in v2 (backend)

- **Triage fix:** the weighted formula `0.55·text + 0.30·rules + 0.15·hotspot` capped a text-only
  request near 48, so "trapped on the roof" ranked *medium*. v2 adds a baseline (flags and hotspots
  can only raise a score: `max(weighted, 0.8·text)`) and safety floors (life-threatening phrases ≥ 82,
  serious ones ≥ 58).
- **Misuse screening** (`screening.py`): max 3 open requests per number (extra ones become updates),
  duplicate detection (same number, or within 250 m with similar text in 30 min), junk text,
  copy-paste bursts, GPS/pin mismatch, trust score per number (recovers over 30 days), blocklist,
  audit log, idle volunteer claims released after 20 min. Nothing is ever rejected.
- **SMS gateway** (`POST /api/sms/incoming`, JSON or Twilio form) with auto-replies at each status change.
- **Offline outbox sync** (`POST /api/requests/sync`): requests sent by SMS while offline are matched to
  the gateway's copy and receive the full details and video.
- **Video/voice upload** (`POST /api/requests/{id}/media`, max 100 MB).
- **Volunteer registration + approval**, availability, one-time phone verification, flood alerts with
  SMS to subscribers, shared forecast conditions and district threat levels.
- **Privacy:** citizens only receive full details of their own requests (recognised by device);
  others' requests arrive without descriptions, names or locations.
- **Rate limits** per network (generous — mobile carriers put many phones behind one address).

### Main endpoints
`GET /api/state` (everything the app shows, filtered by who's asking) ·
`POST /api/requests` · `POST /api/requests/{id}/media|details|cancel` · `POST /api/requests/sync` ·
`POST /api/sms/incoming` · `POST /api/otp/send|verify` ·
`POST /api/auth/login|logout|register` · `GET /api/auth/me` · `PATCH /api/me` ·
`PATCH /api/requests/{id}` · `POST /api/requests/{id}/claim|outcome|verify|merge|not-duplicate` ·
`POST /api/reporters/{key}/block|unblock` · `PATCH /api/users/{id}` · `PUT /api/zones/{district}` ·
`PUT /api/risk/conditions` · `POST /api/alerts` · `POST /api/alerts/subscribe` ·
`GET /api/hotspots` · `GET /api/stats` · `GET /api/health`. Interactive docs at `/docs`.

## 8. Known limitations (honest list)

- **Not built into an APK here:** the build environment used to prepare this had no Android SDK; the
  project was generated with Capacitor 8.5.2 and needs one build in Android Studio.
- **Sessions and one-time codes live in memory:** restarting the server signs staff out.
- **Street map tiles** come from OpenStreetMap, fine for a demo; a public release needs a tile provider
  or offline district tiles. District outlines always work offline.
- **No push notifications yet:** flood alerts show when the app is open and go by SMS to subscribers.
  Push needs a Firebase project (`@capacitor/push-notifications` + `google-services.json`).
- **Voice capture:** some phones open a file picker instead of a recorder for audio.
- **Flood risk** is a transparent weighted index from past disasters, IMD warning, rain and dam levels,
  entered by the control room — not a trained forecast.
- **Malayalam text** should be reviewed by a native speaker before public use.
